# eVTOLs_LYBE — симулациона анализа управљања флотом

Дискретно-догађајна стохастичка симулација eVTOL превоза између Аеродрома Никола Тесла и пет предложених градских вертипортова. Пројекат обухвата учитавање и проверу улаза, генерисање путничких захтева, груписање путника, доделу летелица, летове, пуњење, чишћење, инфраструктурна ограничења и статистичке извештаје.

Документација је усклађена са кодом и резултатима коришћеним у коначној верзији семинарског рада. Претпоставке модела нису сертификоване оперативне карактеристике стварне услуге.

## Обухват семинарског рада

| Поставка | Усвојена вредност |
|---|---|
| Летелица | Archer Midnight, 4 путничка места |
| Флота | 6 летелица |
| Мрежа | LYBE, BW Marina, Хотел Југославија, Марина Дорћол, Бањички вис и EXPO |
| Почетни распоред | 3 LYBE + 2 BW + 1 Хотел Југославија |
| Ред летења | Синтетички сценарио за 31. јул 2026. |
| Основна тражња (`low`) | 1% O&D путника, односно путника који нису у трансферу |
| Репликације | 100 независних репликација |
| Основно семе | `20260920` |
| Брзина крстарења | 200 km/h |
| Снага крстарења | 215 kW |
| Моделовани употребљиви капацитет батерије | 142 kWh |
| Енергетски услов за полазак | 1,10 × планирана енергија лета + 30 kWh резерве |
| Чишћење | 10 минута после 10 завршених путничких летова; позициони летови се не броје |

Временска зона је `Europe/Belgrade`. Захтеви везани за изабрани ред летења могу настати претходног дана или после поноћи наредног дана. Симулација почиње најранијим генерисаним захтевом и завршава се када су сва генерисана путовања завршена, осим ако се утврди застој/неизводљивост.

Нема обавезног враћања слободних летелица на аеродром. Шест летелица представља испитану основну конфигурацију; овим експериментом није доказана минимална потребна флота.

## Инсталација

Потребни су Python 3.10 или новији, NumPy и доступна база временских зона. Из главног директоријума пројекта:

```bash
python -m pip install -r requirements.txt
python -m pip install numpy tzdata
```

У приложеном `requirements.txt` NumPy није наведен, иако га генератор тражње користи, зато је наведен и други корак. Метаподаци провереног извоза тражње бележе NumPy **2.3.5**. За репродукцију тог окружења употребити одговарајућу верзију Python-а и `numpy==2.3.5`, уз исте улазе, код и семе.

На Windows-у се може користити `py` уместо `python`.

## Покретање конфигурације из рада

Провера улаза без покретања симулације:

```bash
python run_sim.py --mode single_configuration --scenario low --fleet-size 6 --replications 100 --seed 20260920 --check-only
```

Пун експеримент:

```bash
python run_sim.py --mode single_configuration --scenario low --fleet-size 6 --replications 100 --seed 20260920
```

**Важно:** у актуелном `run_sim.py` подразумевани CLI режим је `fleet_study`, независно од `run.mode` у конфигурацији. За обухват семинарског рада увек навести `--mode single_configuration`. У приложеном `config.json` стоји `run.replications = 3`; команда изнад то замењује са 100 само за текуће покретање.

Пре покретања проверити да у `config.json`, у `ground_handling.cleaning`, стоји:

```json
{
  "every_completed_legs": 10,
  "duration_min": 10,
  "include_repositioning_legs": false
}
```

Ово је извод из конфигурације, а не замена целог JSON фајла.

### Додатне опције

- `--config putanja/do/config.json`: други конфигурациони фајл.
- `--output-dir outputs/naziv_eksperimenta`: одредиште резултата; за нови експеримент користити нов директоријум.
- `--detailed`: додатни подробни дневници у директоријуму `debug`.
- `--service-target 0.95`: циљни средњи удео правовременог укрцавања.

Путање из конфигурације рачунају се од директоријума у којем се налази `config.json`. Подразумевани конфигурациони фајл налази се поред `run_sim.py`.

Код подржава и режим `fleet_study` и сценарије `medium`/`high` (3%/5% O&D). Њихово постојање у коду не значи да су испитани у овом семинарском раду. Стари примери у другим упутствима који покрећу претрагу флота нису команда за експеримент приказан овде.

## Излазни фајлови и Excel

Без посебног `--output-dir`, резултати се чувају у новом директоријуму `outputs/study_<време>`. За основну конфигурацију добијају се:

- `low_dem_n6_reps.csv`: један ред по репликацији; за 100 репликација индекси су 0–99.
- `low_dem_n6_reps_summary.csv`: збирни статистички показатељи експеримента.

CSV користи UTF-8 са BOM, **тачку-зарез** као раздвајач и **децимални зарез**. У Excel-у, ако се колоне не раздвоје аутоматски, користити **Data → From Text/CSV**, UTF-8 и раздвајач **Semicolon**. Удели су бројеви од 0 до 1; вредност `0,95` приказује се као 95% применом процентног формата. Празно поље није нула.

Основни показатељи обухватају тражњу, завршена путовања, чекање до укрцавања и полетања, услугу по полазним вертипортовима, путничке и позиционе летове, попуњеност, енергију и дијагностику кашњења.

Суфикси `__mean`, `__std`, `__ci_low`, `__ci_high` и `__n` означавају средину, стандардну девијацију, границе интервала поверења и број употребљивих вредности. Јединица статистичког посматрања је независна репликација. Проверити статусе завршетка и број репликација пре тумачења средина.

## Критеријум услуге и тумачење резултата

Путник је правовремено опслужен ако започне укрцавање најкасније 15 минута после захтева. То није време до полетања.

Циљ је да аритметичка средина удела правовремено опслужених путника по репликацијама буде најмање 95%. Не захтева се да свака репликација достигне 95%. Прекорачење рока не прекида опслуживање и само по себи не значи неизводљиву репликацију.

Попуњеност путничких летова у репликацији рачуна се као број превезених путника подељен са четири пута број путничких летова. Позициони летови нису у имениоцу овог показатеља; њихов удео приказује се посебно.

Модел прати одступање од циљног доласка на аеродромски терминал, али **не класификује пропуштене авионске летове**. Кашњење према циљном доласку не сме се тумачити као доказ пропуштеног лета.

## Проверени резултати коначног експеримента

Следеће вредности потичу из провереног узорка од **100 репликација**, са `include_repositioning_legs = false`:

| Показатељ | Резултат |
|---|---:|
| Просечна тражња | 243,78 путника |
| Средњи ниво услуге | 96,87% |
| 95% интервал поверења за средњи ниво услуге | 96,56–97,18% |
| Репликације са нивоом услуге најмање 95% | 84 од 100 |
| Просечно чекање до укрцавања | 12,46 min |
| Просечно време од захтева до полетања | 18,03 min |
| Просечан број путничких летова | 162,75 |
| Просечан број позиционих летова | 92,70 |
| Просечна попуњеност путничких летова | 37,46% |
| Просечан удео позиционих летова | 36,24% |
| Просечна енергија летења | 8.526,13 kWh |
| Просечна енергија летења по путнику | 35,00 kWh/путнику |

Сви путници су превезени у свих 100 репликација. Енергија летења није укупна електрична потрошња целог система. Наведене средине односе се на статистике репликација.

Стари резултат од **95,23%** припада претходној конфигурацији у којој су позициони летови улазили у бројач за чишћење. Не мешати га са коначним резултатима. Ранија дијагностичка провера на две репликације такође није узорак за ове збирне статистике.

## Дијагностика кашњења

- `cause_*` описује ограничења забележена током чекања путника. Позициони лет означава да летелица тада лети празна по путнике; не објашњава сам по себи зашто није раније кренула.
- `preposition_*` прати ограничења повезана са касним поласком стварно коришћене летелице, у односу на најкаснији полазак који би омогућио правовремено укрцавање. Обухвата претходни задатак, батерију, чишћење, ресурсе, припрему и ограничења при додели.

Времена ова два нивоа **не сабирају се**, јер могу описивати исти ланац кашњења. Преклапања ограничења приказују се засебно. Путнички минути нису исто што и трајање застоја једне летелице.

`assignment_unresolved` се у раду назива **„Ограничења при додели летелице“**: обухвата интервале у којима није постојала додела или се привремено изабрана летелица разликовала од оне која је коначно извршила превоз. За те интервале није извршено даље раздвајање по оперативним ограничењима. Ово не доказује да је сама промена доделе изазвала кашњење. Потврђени позициони задатак везује летелицу за групу.

## Прекид и наставак

Током извршавања, `study_checkpoint.sqlite3` чува завршене репликације. Прекинути експеримент наставља се командом:

```bash
python run_sim.py --resume "outputs/study_STVARNI_NAZIV"
```

Ако је коришћен посебан конфигурациони фајл, поново навести исти `--config`. Не користити `--resume` и `--output-dir` заједно. Наставак проверава усклађеност кода, улаза и поставки; измењени експеримент покреће се засебно. После успешног завршетка контролна датотека се уклања.

Излазни кодови: `0` — успешан завршетак/провера, `2` — грешка, `3` — преостала контролна датотека и непотпун/непотврђен исход, `130` — кориснички прекид.

## Структура пројекта

| Фајл | Намена |
|---|---|
| `run_sim.py` | Командна линија, провера улаза и покретање/наставак експеримента |
| `config.json` | Тражња, оперативна правила, енергија, пуњење и експеримент |
| `data/eVTOL_spec.json` | Спецификација моделоване летелице |
| `data/vertiport_network.json` | Мрежа, руте, инфраструктура и почетни распоред |
| `data/lybe_peak_day_2026-07-31.json` | Синтетички ред летења; стварна путања задаје се у конфигурацији |
| `src/input_data.py` | Учитавање, валидација и калибрација улаза |
| `src/entities.py` | Путници, летелице и друге структуре модела |
| `src/demand.py` | Стохастичко генерисање путничких захтева |
| `src/flight_model.py` | Трајање и енергија лета |
| `src/charging.py` | Пуњење батерије у зависности од SOC-а |
| `src/resources.py` | Инфраструктурни ресурси и резервације |
| `src/dispatch.py` | Груписање и додела летелица |
| `src/simulation.py` | Догађаји и ток једне репликације |
| `src/diagnostics.py` | Праћење ограничења и кашњења |
| `src/results.py` | Показатељи, статистика и CSV извоз |
| `src/experiment.py` | Репликације, претрага флота и контролна датотека |

Времена лета су детерминистичка за усвојену руту и профил лета. Стохастика обухвата генерисање путника, избор градског вертипорта и поједине компоненте времена доласка/приступа. Нису моделовани временски услови, случајна кашњења авионских летова или откази летелица.

## Подаци за график дневне тражње

Уз рад су засебно припремљени `hourly_demand.csv`, `hourly_by_replication.csv`, `passenger_requests.csv`, `replication_checks.csv` и `demand_metadata.json`. Они нису подразумевани излаз горње команде за симулацију.

Часовни график приказује **времена настанка захтева**, а не укрцавања или полетања. Средине по часовима укључују свих 100 репликација, укључујући нуле. За приказ у Excel-у користити наслагане стубиће за смерове аеродром → град и град → аеродром, са датумом и часовним интервалом на хоризонталној оси.
